SUMMARY: As-of 13:01 (working tree is being edited concurrently; see notes for mtimes/md5). The STATE layer was rewritten at 12:45 (lib/services/automation_state.dart 2936 lines, command_pipeline.dart, capabilities.dart, endpoint_sync.dart, test/support fakes) and now implements most of CONTRACTS section 5 for the lock: Capabilities gate inside toggleChildLock, per-key CommandPipeline with immediate rollback on 409 DEVICE_OFFLINE / 403 / 502 / network / delivered=false / device_online=false (verified by scratch probes run against a snapshot of the tree), MQTT state.child_lock + LAN poll sync (childLockKnown honoured), REST snapshot on selectHome/resume, reset on logout/home switch/guest expiry, LAN call carrying X-Device-Key. The UI and the test were NOT migrated: device_settings_page.dart, dashboard_page.dart, relay/shutter/DI widgets and test/child_lock_and_night_notification_test.dart are the pre-refactor versions (mtime 09-23..09-30). They do not compile (flutter analyze --no-pub on the audited files: 20 issues: isMember removed, generateServiceToken, JoinHomeResult[], ShutterItem pairIndex, EndpointModel int ids), never read capabilities/commandFailures, and have no unknown/pending/stale state, no confirmation to disable, no screen-reader label, no lock affordance on cards, and a title that is unreadable in the light theme. Remaining state/pipeline bugs found with probes: (1) a REST-derived snapshot falsely confirms an in-flight UNLOCK and the later REST failure is swallowed (UI shows unlocked while the device stays locked); (2) `if (ok) _childLock = enabled` (automation_state.dart:2299) makes the 2.5 s rollback ineffective (snackbar says rolled back, Switch stays on); (3) the confirm timer starts at submit, so REST latency causes false timeouts; (4) a stale GET /child-lock overwrites a newer MQTT state; (5) the lock is a plain bool, so unknown/offline is shown as 'Devre Disi'. The existing child-lock tests only assert the optimistic bool (they pass only because the old toggle never rolled back), never reach cloudApi.setChildLock, and now fail to compile; with the new gating they would fail by design and must be rewritten on top of test/support/fakes.dart.
